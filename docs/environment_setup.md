## §0. クイックスタート（3 分で動かす）

```powershell
# 1. リポジトリ取得
git clone <repo-url> C:\dev\learnapp
cd C:\dev\learnapp

# 2. 環境変数セットアップ（必ず dot-source）

# 4. .env 配置（テンプレを参考に）

# → SUPABASE_URL / SUPABASE_ANON_KEY を編集

# 5. ビルド
```

## §1. 前提とインストール

- Windows 10/11（推奨 RAM 16GB+、ストレージ空き 20GB+）
- macOS 13+（妻の Mac、iOS ビルド時のみ）
- Linux Ubuntu 22.04+（将来の CI、本書では将来検討）

### 1.2 ソフトウェア前提

| ソフトウェア | バージョン | 入手 |
|-----------|---------|------|
| Node.js | 20.x LTS | https://nodejs.org/ |
| Git | 2.40+ | https://git-scm.com/ |
| Android Studio | Hedgehog 2023.1.1+ | https://developer.android.com/studio (JBR と SDK が同梱される) |
| PowerShell 5.1+ | Windows 標準 | （Windows 10/11 同梱） |

Android Studio をインストールするだけで以下がそろう:
- JBR（Android Studio 同梱の OpenJDK 21）: `C:\Program Files\Android\Android Studio\jbr`
- Android SDK: `C:\Users\<user>\AppData\Local\Android\Sdk`
- platform-tools (adb): SDK 内
- AVD Manager + エミュレータ: SDK 内

**JBR と Java を別途インストールする必要はありません**（JBR で完結）。

### 1.3 推奨追加ツール
- VSCode + Expo / React Native 拡張
- Android Studio の AVD Manager で Pixel_7 AVD を 1 つ作っておく

## §2. リポジトリ取得 + 初回セットアップ

### 2.1 推奨パス
**`C:\dev\learnapp\`** を強く推奨。

理由（学習事項 #2 / §1.2 で詳述）:
- 完全 ASCII パス → Android Gradle Plugin の非 ASCII 警告を確実に回避
- 短いパス → CMake / Ninja の Windows long path 制限（260 字）を避ける
- 上位フォルダに日本語が無い → 関連ツール全体で文字化けが起きない

### 2.2 セットアップ手順

```powershell
# 1. クローン
git clone <repo-url> C:\dev\learnapp
cd C:\dev\learnapp

# 2. 環境変数セットアップ (PowerShell)
. .\scripts\setup_env.ps1
# → JAVA_HOME / ANDROID_HOME / PATH を現プロセス + User scope に設定

# 3. npm 依存インストール
npm install

# 4. .env 作成
copy .env.example .env
# .env を編集して SUPABASE_URL / SUPABASE_ANON_KEY を実値に置換

# 5. prebuild + ビルド
npx expo prebuild --platform android --clean
npx expo run:android --variant release
```

### 2.3 Git Bash / WSL を使う場合

```bash
cd /c/dev/learnapp
source scripts/setup_env.sh
npm install
cp .env.example .env
# .env を編集
npx expo prebuild --platform android --clean
npx expo run:android --variant release
```

## §3. 永続化された設定の仕組み

### 3.1 全体像

```
app.config.ts
   ├── plugins/withCustomGradleProperties.js  → android/gradle.properties に 5 プロパティ注入
   └── plugins/withLocalProperties.js          → android/local.properties を sdk.dir で生成

scripts/setup_env.ps1                          → JAVA_HOME / ANDROID_HOME / PATH 設定（PowerShell）
scripts/setup_env.sh                           → 同上（Bash 系）
```

### 3.2 `plugins/withCustomGradleProperties.js`

`npx expo prebuild` 実行時に `android/gradle.properties` へ以下 5 プロパティを冪等注入:

| キー | 値 | 目的 |
|------|---|------|
| `android.overridePathCheck` | `true` | 非 ASCII パスでも AGP 警告で停止しない（Windows 限定発火、他 OS で無害） |
| `reactNativeArchitectures` | `armeabi-v7a,arm64-v8a,x86,x86_64` | フル ABI（リリース APK 形式） |
| `org.gradle.jvmargs` | `-Xmx4g -XX:MaxMetaspaceSize=512m` | Gradle JVM ヒープ 4GB（学習事項 #1 の OOM 抑止） |
| `org.gradle.workers.max` | `1` | Gradle ワーカーをシングルスレッド化（学習事項 #1, #9 への構造的防御） |
| `org.gradle.daemon` | `false` | Gradle daemon 無効化（学習事項 #4 STATUS_DLL_INIT_FAILED 回避） |

開発時の ABI 短縮は環境変数で（永続設定は変えない）:

```powershell
$env:ORG_GRADLE_PROJECT_reactNativeArchitectures='x86_64'; npx expo run:android
```

### 3.3 `plugins/withLocalProperties.js`

`npx expo prebuild` 実行時に `android/local.properties` を自動生成:

```properties
# Auto-generated by plugins/withLocalProperties.js
# Do NOT edit manually — re-run `npx expo prebuild` to regenerate.
sdk.dir=C:\\Users\\masah\\AppData\\Local\\Android\\Sdk
```

SDK パスの検出順序:
1. `$env:ANDROID_HOME`（setup_env.ps1 で設定された値が最優先）
2. `$env:ANDROID_SDK_ROOT`
3. `C:\Users\<USER>\AppData\Local\Android\Sdk`（Windows デフォルト）
4. `~/Library/Android/sdk`（macOS デフォルト）
5. `~/Android/Sdk`（Linux デフォルト）

学習事項 #5 への対応: `expo prebuild --clean` で local.properties が削除されても、次回 prebuild で自動再生成されるため `SDK location not found` エラーは構造的に起きない。

### 3.4 `scripts/setup_env.ps1` / `setup_env.sh`

**学習事項 #7 への対応の中核**: Claude Code の非対話 PowerShell プロセスは User/Machine scope の永続環境変数を継承しないことがある。そのため毎セッション先頭で dot-source する必要がある。

両スクリプトは以下を実行:
1. JBR / Android SDK の自動検出
2. `JAVA_HOME` / `ANDROID_HOME` / `ANDROID_SDK_ROOT` / `PATH` を **現プロセス内** に export（即時反映）
3. （オプション）User scope に永続化（次回シェル起動時から有効）

## §4. 日常運用フロー

### 4.1 ビルド前のお決まり手順

```powershell
cd C:\dev\learnapp
. .\scripts\setup_env.ps1     # ★ 毎回 dot-source（学習事項 #7）
npx expo run:android --variant release
```

### 4.2 `--clean` を打つ時（依存追加 / Expo SDK 更新時）

```powershell
. .\scripts\setup_env.ps1
npx expo prebuild --clean --platform android
# → gradle.properties + local.properties が自動再生成される
npx expo run:android --variant release
```

**学習事項 #5 が解決済み**: `local.properties` が消えても次の prebuild で復活する。

### 4.3 開発時の ABI 短縮（ビルド時間半減）

```powershell
. .\scripts\setup_env.ps1
$env:ORG_GRADLE_PROJECT_reactNativeArchitectures='x86_64'
npx expo run:android       # → APK 74MB、ビルド 5〜6 分
```

リリース時は env 変数を unset / 新規 PowerShell セッションで実行 → フル ABI（210MB）に戻る。

### 4.4 検証コマンド集

```powershell
# 環境変数が正しく入っているか
$env:JAVA_HOME ; $env:ANDROID_HOME

# Java / adb の動作確認
java -version
adb devices

# Gradle プロパティが注入されているか
Get-Content android\gradle.properties | Select-String -Pattern "overridePathCheck|reactNativeArchitectures|jvmargs|workers.max|daemon"

# local.properties が存在するか
Test-Path android\local.properties
Get-Content android\local.properties
```

## §5. macOS（妻の Mac）での iOS ビルド

### 5.1 セットアップ

```bash
# 1. クローン
git clone <repo-url> ~/dev/learnapp
cd ~/dev/learnapp

# 2. 環境変数セットアップ
source scripts/setup_env.sh
# → macOS の Android Studio.app から JBR を検出

# 3. CocoaPods（iOS 用）
sudo gem install cocoapods   # 初回のみ
# or Homebrew: brew install cocoapods

# 4. 依存インストール
npm install
cd ios && pod install && cd ..

# 5. ビルド
npx expo run:ios
```

### 5.2 注意点

- `withCustomGradleProperties` プラグインは macOS でも load されるが、**Android 側にしか影響しない**（iOS ビルドには無関係）
- `withLocalProperties` は macOS デフォルト SDK パス `~/Library/Android/sdk` を検出する
- iOS ビルドだけなら Android SDK が無くてもエラーにならない（withLocalProperties は警告だけ出して skip）

## §6. Linux / GitHub Actions（将来）

### 6.1 GitHub Actions のセットアップ例

```yaml
# .github/workflows/build-android.yml（将来サンプル）
name: Build Android
on: [push]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: bash scripts/setup_env.sh
        env:
          ANDROID_HOME: /usr/local/lib/android/sdk
      - run: npm ci
      - run: npx expo prebuild --platform android --clean
      - run: npx expo run:android --variant release
```

### 6.2 注意点

- Linux では `org.gradle.daemon=false` は不要（むしろ性能低下）→ `eas.json` の env で `org.gradle.daemon=true` 上書きを検討
- `android.overridePathCheck=true` は Linux でも無害（発火しない）

## §7. トラブルシュート（学習事項 #1〜#11 全反映）

### 7.1 学習事項 #1: jest-worker child process exception

**症状**: Metro 起動時に `Cannot find module 'jest-worker'` 系 / child process exception で fatal

**対処**: `metro.config.js` で `config.maxWorkers = 1`（既反映済）
**理由**: Windows + Node v22 + Expo SDK 52 + 大規模依存ツリーで jest-worker の child process が並列クラッシュ
**副作用**: dev bundle 速度 +12〜15 秒、本番 (Metro 不使用) に影響なし

### 7.2 学習事項 #2: 非 ASCII パスでビルド失敗

**症状**: `Your project path contains non-ASCII characters` 警告 → CMake / Ninja で long path / Shift-JIS エラー連鎖

**対処**:
1. リポジトリを `C:\dev\<short_name>\` に移転（推奨）
2. `android.overridePathCheck=true` で AGP 警告抑止（プラグインが自動注入）

**理由**: AGP は Windows での non-ASCII path で保守的に停止する。上位フォルダに日本語が残ると発火するため、設定で抑止が必須

### 7.3 学習事項 #3: adb start-server エラー 3221225794

**症状**: `adb devices` 等で `exited with non-zero code: 3221225794`

**対処**:
```powershell
adb kill-server
adb start-server
```

**理由**: Windows での DLL ロード問題（同コード = STATUS_DLL_INIT_FAILED）。kill→start で復旧

### 7.4 学習事項 #4: gradle.exe STATUS_DLL_INIT_FAILED

**症状**: `gradlew` 実行で `exited with non-zero code: 3221225794`

**対処**: `org.gradle.daemon=false`（プラグインが自動注入）
**理由**: gradle daemon 起動時の Windows DLL ロード問題を構造的に回避
**副作用**: ビルド起動 +5〜10 秒、累積 +20〜30 秒。安定性優先

### 7.5 学習事項 #5: `local.properties` が `prebuild --clean` で削除

**症状**: `npx expo prebuild --clean` 後 `SDK location not found` で即失敗

**対処**: `plugins/withLocalProperties.js` で自動再生成（既反映済）
**理由**: `expo prebuild --clean` は `android/` 全体を一度削除して再生成。`local.properties` は git 管理外なので消える。プラグインが prebuild の post hook で再生成

### 7.6 学習事項 #6: 環境変数の引継ぎミス

**症状**: 別ターン / 新規 PowerShell セッションで `java: command not found` / `adb: command not found`

**対処**: 毎セッション先頭で `. .\scripts\setup_env.ps1`（dot-source 必須）
**理由**: 次項 #7 と密接、Claude Code の非対話 PowerShell は永続環境変数を継承しない

### 7.7 学習事項 #7: PowerShell 非対話モードは永続環境変数を継承しない（最重要）

**症状**: User scope に `JAVA_HOME` をセットしてもターンを跨ぐと消える

**対処**:
- Claude Code から PowerShell を叩く時は必ず `setup_env.ps1` を dot-source
- スクリプト自体は永続化も行うが、現プロセスへの即時 export が本質
- 人間が手元で叩く時は新規 PowerShell ターミナルを開けば User scope の永続値が読まれる

**理由（推定）**: `-NonInteractive` モードでは User profile / `$PROFILE` が読まれず、永続環境変数の継承簡略化が行われる

### 7.8 学習事項 #8: idle 通知の文脈依存解釈

これは秘書（team-lead）側の運用知見。エージェント実装者には直接関係なし。
詳細は `feedback_proactive_status_management.md` 参照。

### 7.9 学習事項 #9: Expo SDK 52 + RN New Arch で minifyReleaseWithR8 が出ない

**症状**: `gradlew app:assembleRelease` のタスク列に `:app:minifyReleaseWithR8` が出現しない

**対処**: これは **エラーではなく仕様**。Expo の default release config が `minifyEnabled = false` のため
**注意**: 前任の「R8 段階で失敗」仮説は誤り。Windows STATUS_DLL_INIT_FAILED の root cause は §7.4 の通り gradle daemon の DLL 問題

### 7.10 学習事項 #10: adb pull の Git Bash path 変換問題

**症状**: `adb pull /sdcard/file.png /c/dev/...` が MSYS のパス自動変換で fail

**対処**:
```bash
MSYS_NO_PATHCONV=1 adb pull /sdcard/file.png "C:\dev\learnapp\screenshot.png"
```
- 第 1 引数（端末側パス `/sdcard/...`）は自動変換を抑止
- 第 2 引数（destination）は Windows path `C:\...` で渡す
- `scripts/capture_screenshots.sh` には `cygpath -w` で auto-convert 実装済

**理由**: Git Bash (MSYS) は `/c/...` をパスとして自動的に `C:\...` に変換しようとし、adb の引数解析と衝突する

### 7.11 学習事項 #11: adb input が RN TextInput を発火しない

**症状**: `adb shell input text 'foo'` で値は入るが、RN の `onChangeText` が呼ばれず state が更新されない

**対処**:
- adb input は使用不可と認識（既存）
- **Maestro** でテキスト入力する（mobile-engineer-3 が導入中）
- E2E テスト書く時は最初から Maestro 前提で

**理由**: RN は SyntheticEvent ベース、ネイティブ EditText の値変更を React 側に伝播しない

### 7.12 追加発見（本セットアップで判明）: PS1 BOM 付き UTF-8 必須

**症状**: 日本語コメントを含む `.ps1` を BOM 無し UTF-8 で保存すると、PowerShell 5.1 が Shift-JIS と誤判定して構文エラー（46 行目 `)` invalid 等）

**対処**:
- `.ps1` ファイルは必ず BOM 付き UTF-8 で保存
- VSCode の場合: 右下 `UTF-8` → `Save with Encoding` → `UTF-8 with BOM`
- スクリプト経由で BOM 付加: `node -e "fs.writeFileSync('file.ps1', '﻿' + fs.readFileSync('file.ps1','utf8'))"`

**理由**: PowerShell 5.1 はデフォルトで Windows-1252 / Shift-JIS と推定する。BOM がないと UTF-8 を認識できない

## §9. FAQ

**Q1. なぜ JBR (OpenJDK 21) で、JDK 17 や JDK 11 ではないのか?**

A. Expo SDK 52 + RN 0.76+ は JDK 21 をサポート、Android Studio Hedgehog 以降は JBR 21 同梱。JDK 17 でも動作するが、JBR が最も検証されているため統一。社内の他環境で JDK 17 を強制したい場合は `setup_env.ps1` の `$candidates` の先頭に JDK 17 パスを追加して優先度操作可能。

**Q2. `org.gradle.daemon=false` でビルドが遅くなる。on にできないか?**

A. **Windows でのみ** 学習事項 #4 STATUS_DLL_INIT_FAILED を回避するために off にしている。Linux / macOS では `eas.json` の env で `org.gradle.daemon=true` を上書きすることで局所的に有効化可能（§6.2 参照）。MVP 期間中は安定性を優先し、性能改善は EAS Build 移行時に再検討。

**Q3. 新しい PC でセットアップする手順は?**

A. §2 の通り。`. .\scripts\setup_env.ps1` を必ず最初に走らせる。これで Android Studio が標準パスにインストールされていれば検出される。標準パスに無い場合は `setup_env.ps1` の `$candidates` 配列を編集。

**Q4. プラグインが load されない**

A. §7.4 参照（withGradleProperties API シグネチャ）。`EXPO_DEBUG=1 npx expo prebuild` でログを取り、`Plugin loaded: withCustomGradleProperties` が出るか確認。

**Q5. 既存の `gradle.properties` 設定を残したい**

A. `withCustomGradleProperties` の `upsertProperty` は **既存キーがあれば値を更新、無ければ追加** の冪等動作。Expo SDK が他のキー（`android.useAndroidX` 等）を入れる場合、それらは残る。プラグイン側で管理する 5 キーだけが上書き対象。

**Q6. プラグインの動作を一時的に無効化したい**

A. `app.config.ts` の plugins 配列で該当行をコメントアウト → `npx expo prebuild --clean` で再生成。プラグインを完全削除した状態の `android/` で従来の手動修正が必要かどうか確認できる。
